# 最小改造路线图

## 原则

- 以 v2.7 为基线，小步提交，不先重写 845 行 `content.js`。
- 先保证字幕翻译正确，再改善朗读，最后接入音频后端。
- 每阶段都保留 YouTube 官方字幕翻译和 Web Speech API 回退。
- 未建立测试与授权流程前，不采集或上传用户音频。

## P0：建立可验证基线

目标：让后续修改能确认没有破坏现有英语流程。

- 保存韩语、英语、日语各至少一个人工字幕和自动字幕样本。
- 为 json3/XML parser、轨道排序、语言归一化和 cue 匹配增加最小测试。
- 记录 YouTube 官方翻译、MyMemory 回退和实时字幕三条路径的预期结果。
- 增加可取消请求和视频世代标识，防止切换视频后旧请求回写。

验收：三种语言样本可以离线验证解析；英语现有路径行为保持一致；切换视频不会显示前一视频结果。

## P1：完成韩/英/日字幕翻译

目标：不引入音频处理，先修正语言路由。

- cue 增加 `sourceLang` 与 `targetLang`。
- 轨道选择优先用户指定或自动识别的 ko/en/ja，而不是固定英语。
- 翻译缓存键改为 provider + sourceLang + targetLang + text。
- 收敛 YouTube 官方翻译和 MyMemory 为统一 translation adapter。
- 批量翻译按播放附近窗口预取，避免长视频全量串行等待。

验收：韩、英、日字幕都能生成中文；失败时明确显示错误，不把外语原文当中文朗读。

## P2：优化 TTS 与基础同步

目标：在不接后端模型时先解决截断和生硬问题。

- 将声音选择、文本清理、队列、取消和播放状态收敛为 TTS 调度器。
- 新字幕不再无条件取消当前句；设置最大积压和过期丢弃策略。
- 处理暂停、跳转、倍速和视频切换。
- 记录实际 utterance 开始/结束时间，为后端 TTS 接口准备指标。

验收：正常语速下句子不被频繁截断；暂停/跳转不会继续播放过期语音；落后超过阈值时能恢复到当前字幕。

## P3：建立后端能力边界

目标：先接通安全、可替换的服务接口，不立即引入全部模型。

- 建立翻译 API 和异步音频任务 API。
- 加入认证、限流、超时、取消、请求 ID 和错误码。
- 明示字幕/音频会发送到后端，并要求用户主动启用音频增强。
- 后端先实现一个翻译 provider 和一个 TTS provider，保留 provider adapter。

验收：密钥不进入扩展包；后端不可用时基础字幕和本地 TTS 仍可运行。

## P4：音频增强与多说话人

目标：按依赖顺序建立完整音频链路。

1. 音频采集、分块、重采样和上传。
2. 降噪与人声增强，并用客观指标和人工样本比较前后效果。
3. 说话人分离/聚类和 ASR，输出带 speakerId 的时间段。
4. 翻译与分角色 TTS，保留每段目标时长。
5. 强制对齐、时间伸缩和插件端音频调度。

验收：两人样本能稳定产生两个说话人轨道；生成语音与字幕时间轴一致；处理失败可回退到字幕模式。

## P5：UI 与发布

- 增加源语言、翻译服务、TTS 模式、音色和音频增强开关。
- 显示加载、限流、后端任务进度、降级原因和隐私说明。
- 建立版本清单、手工回归表和最小发布检查。

## 建议优先完成的三个任务

1. **建立三语言字幕样本与最小测试**：当前没有可靠回归基线，直接加模型或音频最容易引入不可见回归。
2. **修复源语言路由并统一 cue/翻译 adapter**：这是韩语和日语支持的最小根因修复，也为后端模型留出单一接口。
3. **重做 TTS 队列与播放器生命周期同步**：无需后端即可解决截断和明显生硬，同时为后端配音调度奠定基础。

音源分离、降噪和人声增强应排在以上三项之后；它们需要新的权限、后端、隐私流程、测试音频和显著计算资源。
