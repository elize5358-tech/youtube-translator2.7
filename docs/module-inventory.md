# 模块清单与能力审计

## 文件清单

| 文件 | 规模 | 当前职责 | 耦合/风险 |
| --- | ---: | --- | --- |
| `content.js` | 845 行 | 字幕、翻译、TTS、UI、状态、同步、导航 | 高耦合；任何改动都可能影响整条链路 |
| `popup.html` | 141 行 | 弹窗结构与内联样式 | UI 简单，但样式和结构无法独立复用 |

| `manifest.json` | 22 行 | MV3 权限与入口 | 无 service worker、音频权限或后端域名 |

## 能力矩阵

| 能力 | 状态 | 说明 |
| --- | --- | --- |
| YouTube 人工/自动字幕发现 | 已有 | 多级回退，但依赖非稳定接口 |
| YouTube 官方字幕翻译 | 已有 | 通过 `tlang`，效果取决于视频和 YouTube |
| 英语 → 中文回退翻译 | 部分已有 | MyMemory，无质量保证、限流治理或隐私提示 |
| 韩语 → 中文 | 缺失 | 轨道可能获取，但 MyMemory 路径错误标记为英语 |
| 日语 → 中文 | 缺失 | 同上 |
| 模型调用层 | 缺失 | 没有统一 provider/model adapter |
| 浏览器基础 TTS | 已有 | Web Speech API，单声线、仅语速可调 |
| 高质量 TTS 配音 | 缺失 | 无后端 TTS、音频文件、角色或缓存 |
| 字幕时间同步 | 部分已有 | 只匹配 cue 时间，不同步朗读时长 |
| 音频采集 | 缺失 | 无 tabCapture/offscreen/service worker |
| 降噪与人声增强 | 缺失 | 无音频处理代码 |
| 音源/说话人分离 | 缺失 | 无波形、声纹或 diarization 数据 |
| ASR | 缺失 | 完全依赖 YouTube 字幕 |
| 前端设置 | 部分已有 | 翻译、朗读、语速；无语言、音色或服务状态 |
| 测试与发布验证 | 缺失 | 无自动化测试和固定样本 |

## 重复逻辑

- `findCaptionTracksInPage` 与 `findCaptionTracksInSources` 重复相同的 JSON 提取循环。
- `translateBatch` 和 `translate` 都检查同一翻译缓存。
- content 与 popup 分别维护设置默认值，已有字段不一致的风险。
- 下载字幕模式和实时字幕模式各自实现“翻译 → 显示 → 朗读”，错误与去重策略不一致。
- 初始化和停止逻辑分别直接清理 TTS、计时器和状态，生命周期没有单一入口。

## 高耦合点

1. `initForVideo` 同时负责网络回退、状态机、UI 文案、翻译策略和错误降级。
2. `pollSubtitles`/`pollLiveCaption` 把同步、翻译、显示和语音播放绑定在一起。
3. 全局闭包状态被多个异步函数读写，缺少请求世代或 AbortController，切换视频时存在旧请求回写风险。
4. 字幕结构只有 `text/start/end`，无法自然承载源语言、说话人、置信度和生成音频。

## 可保留与需迁移

浏览器插件适合保留页面适配、字幕显示、播放器事件、设置、基础本地 TTS 和后端任务控制。密钥、模型翻译、长音频处理、降噪、增强、分离、ASR、神经 TTS 与强制对齐应进入后端。只有用于预览的小型 Web Audio 增益/滤波适合留在浏览器，不能替代生产级降噪和分离模型。
